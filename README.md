# Kasane（重ね）

スマホ（iPhone）でも使える筋トレ記録アプリ。サーバーもアカウントも不要で、データは端末のブラウザ内に保存されます。

名前の由来は「重ねる」。プレートを重ね、セッションを積み重ねる — 前回より1回多く、を記録し続けるためのアプリです。

## 使い方

`start.command` をダブルクリック → ブラウザが開きます。

- **このMacで使う**: http://localhost:8787
- **iPhoneで使う**: **https://<自分のtailnet名>.ts.net:8443** （Tailscale経由。外出先でもつながります）
  → Safariの共有ボタン →「ホーム画面に追加」でアプリのように使えます

### iPhoneで開くアドレスが分からなくなったら

**`アドレス.command` をダブルクリック**してください。

- 自分のtailnet名を調べて、**開くべきURLを表示**します
- **クリップボードにコピー**します
- **QRコードを表示**します。iPhoneのカメラを向けるだけで開けるので、長いURLを手で打つ必要はありません
- Tailscaleの `serve` 設定（HTTPSの受け口）が消えていたら、その場で入れ直します
- サーバーが止まっていたら、それも教えます

QRコードは `tools/qr.py` で作っています（外部ライブラリなし・Macの標準のPython3だけで動きます。
8bitバイトモード／誤り訂正M／バージョン1〜6、106文字まで）。

### ⚠️ URLは1つに固定してください

データは**URL（オリジン）ごとに別々**に保存されます。
`http://192.168.x.x:8787` と `https://<自分のtailnet名>.ts.net:8443` は、**別のアプリとして扱われ記録が共有されません**。
iPhoneでは必ず上のHTTPSアドレスだけを使ってください。

### なぜHTTPSなのか（オフライン動作の条件）

Service Worker は **HTTPS か localhost でしか動きません**。
`http://192.168.x.x:8787` で開くとアプリ自体は動きますが、**オフラインでは開けません**。
ジムで電波が悪いときやMacが寝ているときに使えるよう、iPhoneからはHTTPSのアドレスを使ってください。

Tailscale の設定（設定済み。やり直すとき用）:

```
tailscale serve --bg --https=8443 http://127.0.0.1:8787
```

### サーバーの自動起動（設定済み）

`start.command` を毎回押さなくていいように、**launchd に登録済み**です。
Macのログイン時に自動で起動し、落ちても10秒後に復活します。

2026-07-29 から、中身は `python -m http.server` ではなく **`tools/server.py`** です。
静的配信に加えて、毎朝の通知（下の「体重の測り忘れを防ぐ」）の購読受付とテスト送信を担当します。

- 設定ファイル: `~/Library/LaunchAgents/com.morikastu.kasane.plist`
- ログ: `~/Library/Logs/kasane.log`

| やりたいこと | コマンド |
|---|---|
| 状態を見る | `launchctl print gui/$(id -u)/com.morikastu.kasane` |
| 止める | `launchctl bootout gui/$(id -u)/com.morikastu.kasane` |
| 再開する | `launchctl bootstrap gui/$(id -u) ~/Library/LaunchAgents/com.morikastu.kasane.plist` |

自動起動しているので、`start.command` は基本的に使いません（押しても二重起動はしません）。

## はじめて開いたとき

初回だけ、3つの質問が出ます（週に何回／体の分け方／1回の時間）。答えると曜日ごとの予定が組まれ、
そのまま「今日は◯◯の日」に着地します。**スキップしても使えます**（週3回のPPL・1時間が既定）。

どの質問からも「**戻る**」で1つ前に戻れます（最初の質問からは冒頭の画面に戻ります）。
回数の選択肢には「**週末だけ**」もあります。

あとから変えたいときは、設定タブ →「使い方と用語」→「初期設定をやり直す」。

## ウォームアップとストレッチ

記録タブの上に、**その日やることが具体的に出ます**。項目をタップするとチェックが付き、`3/10` のように進み具合が分かります。

- **トレーニング前（6分）** … 体を温める → その日の部位に合わせた動的ストレッチ → 1種目めの軽いセット
- **トレーニング後（5分）** … その日使った部位の静的ストレッチ（30秒ずつ）
- **休養日** … ストレッチのみ。前もも・胸・お尻＋軽いウォーキング

Pushの日なら「腕回し・肩甲骨・胸を開く・膝つき腕立て」、Legsの日なら「自重スクワット・ヒップヒンジ・ランジ・足首回し」というように中身が変わります。

止めて伸ばす静的ストレッチはトレーニング**後**に置いています。前にやると一時的に力が出にくくなるためです。

各項目の右の「**やり方**」から、その動作の手順とポイント、動画リンクが開きます。
ストレッチや準備運動のやり方が分からないときはここを見てください（27種の動作を解説しています）。

カードはトレーニングを始めると自動でたたまれます（見出しをタップすれば開きます）。

画面右上の **?** から、いつでも次のものが開けます。

- 3ステップの記録手順
- **ウォームアップのやり方**（その日の部位に合わせた内容が出ます）
- 用語（セット／レップ／インターバル／総ボリューム／推定1RM／PPL など）
- 各タブの見かた

### ジムの表示名で探せます（2026-07-27 追加）

ジムのマシンには英語のプレートが貼ってあることが多く、呼び方も店によって違います。
そこで種目に**別の呼び方**を持たせて、種目一覧に小さく併記し、検索でもヒットするようにしました。

- 「CHEST PRESS」「PEC」「ABDUCTOR」「PUSHDOWN」など、**マシンに書いてある英語で検索できます**
- 「バタフライ」→ ペックフライ、「ローイング」→ シーテッドロー のように**別名でも出ます**
- 「やり方」画面には「**ジムの表示**」として全部の呼び方が並びます

呼び方は `data.js` の `ALIAS` にまとまっています。ジムで違う名前を見つけたら、そこに足すだけです。

## 今日のひとこと（記録タブの先頭）

アプリを開くたびに、いちばん上に1枚出ます。中身は3段です。

1. **見出し** — いまの状況。次の順で切り替わります
   - 記録ゼロ … 「ようこそ。ここから始めましょう」
   - 今日もう完了 … 「今日はもう完了しています」
   - 今日やっている途中 … 「今日はここまで◯セット」
   - **前回から4日以上あいている … カードが黄色くなり「前回のトレから◯日空いています」＋背中を押す一言**（`data.js` の `COMEBACK`）。
     空いた日数が長いほど強めの文面から始まります
   - それ以外 … 「前回は7/25(土)の胸」＋「昨日に続けて。いい流れです／◯日空き。ちょうど回復できた頃です」
2. **経過報告** — 記録から自動で拾った数字を2つ。1つめは良い知らせ優先、2つめは日替わりで回ります
   - この7日の自己ベスト更新 ／ 推定1RMの伸び（21日以上前との差） ／ 今月の回数と先月同時期の比較 ／
     今週のセット数と最多部位 ／ 週1回以上の継続週数 ／ 通算回数の節目まであと何回 ／ 累計で持ち上げたトン数 ／
     体重の3週間前比 ／ 今週のウォーキング
   - 数字が足りないものは黙って出ません。記録が増えるほど出てくる項目が増えます
3. **今日のワンポイント** — 45個の豆知識（トレーニング／食事／休養／続けるコツ／ジムでの過ごし方／ケガをしない）が
   日替わりで1つ。「別のを見る」を押すと次のものに進み、経過報告と背中押しの文面も一緒に切り替わります

文章を足したい・変えたいときは `data.js` の `TIPS` と `COMEBACK` を編集してください（末尾に足すだけでOK）。

## 見た目（白ベース）

2026-07-27にダークから**白ベース**に変更しました。種目イラスト（`img/`）が白背景なので、そこに馴染みます。

色は `index.html` 冒頭の `:root` にある8色だけで決まっています。ここを書き換えればアプリ全体の色が変わります。

```css
--bg:#f4f6f9;   /* 画面の地色 */    --card:#ffffff;  /* カード */
--card2:#eef1f6;/* 入力欄・淡いボタン */ --line:#e2e7ef;  /* 罫線・枠 */
--fg:#171a20;   /* 文字 */          --sub:#6c7685;   /* 補足の文字 */
--accent:#2f6fe4;/* 青（強調） */    --ok:#0f9d6b;    /* 緑（完了・達成） */
--warn:#c07800; /* 黄（注意） */     --bad:#dc3545;   /* 赤（削除・NG） */
```

黒に戻したくなったら、この8色を元の値（`--bg:#0f1115` など）に戻せば戻ります。
あわせて `manifest.json` の色と、`<meta name="theme-color">`・`apple-mobile-web-app-status-bar-style` も合わせてください。

## 入力を速くする仕掛け

- **前回値がグレーで表示される**。同じ重量・回数でやるなら、数字を触らず ✓ を押すだけで確定します。変えたいときだけ上書き
- **自己ベストを更新すると通知**が出ます（🎉 自己ベスト更新！）
- **プレート計算** — 目標の総重量を入れると、バーの片側に入れる枚数が出ます（シャフト重量は変更可）
- **プランクなど時間の種目は「秒」で入力**します（30、45、90…）。「▶ 計測」を押すとその秒数のカウントダウンが始まり、
  終わると自動で ✓ が付きます。表示は `90秒` → `1分30秒` のように読みやすく変換されます
- **今日のトレーニングを完了する**ボタンを押すと、その日のまとめ（所要時間・種目数・セット数・総ボリューム・自己ベスト更新・部位別の内訳）が出ます。
  完了後は部位バナーに「✓ 19:08 に完了しました」と出て、「まとめ」からいつでも見返せます（取り消しも可）
- 種目カードの「記録」ボタン → その種目の全履歴・推定1RMの推移グラフ

## 部位別の週間セット数（履歴タブ）

「今週この部位を何セットやったか」が棒グラフで出ます。緑の帯が**週10〜20セット**の目安ゾーン。
帯に届いていない部位はグレー、超えている部位は黄色になるので、「今週は背中が足りない」が一目でわかります。（ ）内は先週の数字です。

推定1RMはEpley式（重量×(1+回数÷30)）。12回以下のセットからのみ算出しています（高レップは誤差が大きいため）。

## 今日はどこの日？

設定タブで**曜日ごとに部位**を決めておくと、記録タブの上部に「今日はPush（押す）の日」と出ます。
分割プリセットから選ぶのが手っ取り早いです。

| プリセット | 中身 |
|---|---|
| PPL 週3回 | 月Push・水Pull・金Legs |
| PPL 週6回（本格） | 月〜土でPPLを2周 |
| PPL 週4回＋有酸素 | 月Push・火Pull・木Legs・金有酸素 |
| 週2回（上半身/下半身） | 月に胸・腕、木に脚・腹 |
| 週3回（王道の3分割） | 月胸・腕／水背中・肩／金脚・腹 |
| 週4回＋有酸素 / 週5回（部位別） | 部位を細かく分ける派向け |
| **週末だけ（土日）** | **土日に全身を2回。平日は行けない人向け** |
| **週末だけ（金土日）** | **金Push・土Pull・日Legs。週末に寄せてPPLを1周** |

### 週末だけの人へ

週2回しか行けないときは、**分割せず「全身」を2回**やるのがおすすめです。
胸の日／背中の日…と分けてしまうと1部位あたり週1回になり、成長が鈍るためです。
全身なら、少ない回数でもすべての部位に週2回の刺激が入ります。

金曜も動けるなら「週末だけ（金土日）」でPPLを1周できます。

**PPL** ＝ 部位ではなく「動作」で分ける方法です。

- **Push（押す）** … 胸・肩・三頭
- **Pull（引く）** … 背中・二頭
- **Legs（脚）** … 脚・腹

同じ筋肉を続けて使わないので回復させやすく、週3回でも週6回でも同じ型で組めます。
部位別の分割とはいつでも切り替えられます（プリセットを押すだけ）。曜日ごとに `Push` と `胸` を混ぜることもできます。

- 予定を変えたい日は、バナー右の「変更」でその日だけ差し替えられます（曜日の設定はそのまま）

### 休養日の「今日のおすすめ」

曜日の予定が休養日でも、**鍛えるなら何がおすすめか**をバナーに出します。

- **最近やっていない＝回復済みの部位**を勧めます（Push／Pull／Legs のうち、前回から一番日が空いているもの）
- 「Pull（引く）・5日空いていて回復済みです」のように理由つきで表示されます
- 「**この部位で始める**」を押すと、その部位に切り替わっておすすめメニューが出ます（曜日の設定は変わりません）
- まだ一度もやっていない部位があれば、それを最優先で勧めます

決まった曜日ローテを組んでいない人でも、開けば「今日はここ」が分かります。休むのも自由で、下に休養日のストレッチも出ます。

## 時間からメニューを組む

記録タブの「今日つかえる時間」で **30分／45分／1時間／1.5時間／2時間** を選ぶと、
その時間に収まるようにメニューが自動で組み直されます。

- **短いとき** … 優先順位の低い種目から外れ、セット数も減ります（「（短縮）」と表示）
- **長いとき** … セット数が増え、それでも余るなら別の種目が足されます（「（増量）」「時間が余ったら」）。
  複数部位の日は、**部位を1つずつ順番に**足していくので偏りません（全身の日で胸ばかりにならない）
- 見積りは **ウォームアップ6分＋1種目あたり準備2分＋1セット（動作40秒＋インターバル）** で計算しています。
  **インターバルは部位ごとに違う**ので、同じ1時間でも脚の日と腕の日では入るセット数が変わります

例（1時間）:

| 部位 | 中身 |
|---|---|
| Push | ベンチプレス3・インクラインベンチプレス3・ダンベルプレス3・ショルダープレス3・サイドレイズ3・トライセプス3（推定60分・18セット） |
| 脚 | スクワット3・レッグプレス3・レッグカール3・レッグエクステンション3（推定58分・12セット） |
| 腕 | ナローベンチプレス3・アームカール3・トライセプス3・ハンマーカール3（推定34分・12セット） |

脚は休みが3分あるので、12セットで1時間近くかかります。腕は1分なので同じ12セットでも34分です。

## インターバル（部位ごと）

設定タブで**部位ごとに秒数**を決められます。既定値は次のとおりです。

| 部位 | 既定 | 理由 |
|---|---|---|
| 脚 | 180秒 | 全身で一番大きい筋肉。神経系の疲労が大きく、短いと次のセットで重量が落ちます |
| 背中 | 150秒 | デッドリフトなど全身を使う種目が多い |
| 胸 | 120秒 | プレス系の複合種目が中心 |
| 肩 | 90秒 | 中程度 |
| 腕 | 60秒 | 単関節種目。短くてよい |
| 腹 | 45秒 | 同上 |
| 有酸素 | なし | タイマーを出さない |

- セットの ✓ を押すと、**その種目の部位の秒数**でタイマーが動きます
- 「おすすめの秒数に戻す」でいつでも既定値に戻せます
- 秒数を変えると、上の「時間からメニューを組む」の計算にも反映されます

### タイマーの音（2026-07-27 に作り直し）

ジムでは「ピッ」1回では気づけないので、**気づくまで鳴り続ける**方式にしました。設定タブの「タイマーの音」で選べます。

| 設定 | 動き |
|---|---|
| 鳴らさない | 音なし（画面のタイマーは緑に変わります） |
| 6秒 | 6秒間くり返し |
| **20秒（既定）** | 20秒間くり返し |

（「1回」は2026-07-29に廃止。短くて気づけない、という当初の不満そのものだったため。選んでいた場合は6秒として動きます）

**画面のどこかを触ればすぐ止まります。** 「鳴らしてみる」ボタンでその場で確認できます。

仕組みと、そうした理由:

- 音は **Web Audio で鳴らしています**（2026-07-30に `<audio>` 方式から変更）。
  `<audio>` はiOSでメディア音の扱いになり**バックグラウンドの音楽を完全停止させてしまう**
  （しかも復帰は手動）ため、音楽の上に重ねて鳴らせる Web Audio に戻しました
- そのトレードオフとして、**マナーモード（消音スイッチ）中は何も再生していないと鳴らないことがあります**。
  音楽をかけながらなら消音スイッチに関係なく重なって鳴ります。ジムでは音楽を聴きながらが普通なので、こちらを優先
- 音は1175Hzと1568Hzの三連×0.9秒周期。スマホの小さいスピーカーは1〜3kHzがいちばんよく鳴るため、その帯域＋倍音を使っています
- iOSは「一度もタップされていないページ」では音を出せないので、**最初のタップでAudioContextを起こして**います（`ALARM.unlock()`）
- 鳴らす秒数ぶんの音を先にまとめて予約し、タップされたらマスターの線を抜いて一括で止める作りです
- 音量は**iPhoneの音量ボタン**で調整してください
- タイマー中は **Wake Lock で画面が消えないように**しています。画面が消えるとタイマーもアラームも止まるためです

### 増やしすぎない上限

**1回のセッションで、1部位あたり12セットまで**にしています（週10〜20セットの目安を週2回に割った上限）。
これ以上は増やしても効果が伸びにくく、疲労だけが残るためです。

そのため「胸だけの日に1.5時間」を選んでも、12セット・推定40分で組み終わります。
その場合は画面にその旨が表示されるので、余った時間は有酸素やストレッチに回してください。

## 記録のコツ

- 種目を追加すると**前回と同じ重量・回数が自動で入る**ので、変更した分だけ直せばOK
- 種目名の下に「前回 7/20 — 57.5kg×10, 57.5kg×9, 55kg×8」と出るので、前回超えを狙いやすい
- その下に「**次はこれ 62.5kg × 8回**」と次回の目標が出ます（漸進性過負荷）。「入れる」でその重量・回数を空きセットに一括入力
  - 前回10回以上できていたら重量アップ（脚の高重量は+5kg、ダンベル種目は+1kg、その他+2.5kg）
  - 6〜9回なら同じ重量で+1回、それ未満なら同じ重量でフォーム重視
  - 自重種目は+1回、時間種目は+15秒
  - 1セット記録し始めると引っ込みます
- 体重は毎日同じ条件（起床後・トイレ後など）で測ると、グラフの意味が出ます。日々の増減より**7日平均の向き**を見てください

### 計測した時刻も記録されます

体重を記録すると、そのときの時刻が一緒に保存されます（`7:05` のように表示）。

体重は1日のうちで1kg近く動くため、「昨日より増えた」の原因が食事なのか計測時間なのか、あとから判断するのに使います。

- 記録一覧の各行に時刻が出ます
- 3日ぶん以上たまると「**いつもの計測時間は 7:12 ごろ**」と中央値が表示されます
- そこから**2時間以上ずれた日**にはオレンジで「いつもと違う時間」と印が付きます。その日の増減は割り引いて見てください
- 時刻を持たない過去の記録はそのまま扱われます（表示されないだけ）
- 体脂肪率だけをあとから足した場合、時刻は最初のままです。体重の数値を変えた場合だけ、測り直しとみなして時刻が更新されます

## 朝ウォーキングの記録

記録タブに「🚶 朝ウォーキング」カードがあります。歩いた時間（分）を ±5 と「記録」だけで残せます。

- 距離（km）は任意で追加できます
- 記録すると時刻も一緒に残ります
- **今週の合計分数**と**連続記録日数**が出ます
- 直近5日ぶんの記録が下に並びます（× で削除）
- **今日ぶんを記録すると1行に畳まれます**（2026-07-29〜）。直したいときはその行をタップすると開きます

ジムのメニューとは別枠で、筋トレのボリュームや部位別セット数には影響しません（有酸素なので）。
バックアップにも含まれます。

## 食事（カロリーとPFC）

食事タブで、**1日の目標カロリーとPFC（タンパク質・脂質・炭水化物）**を計算し、食べたものを足していけます。

最初に一度だけ、**食事タブの「からだの情報を入れる」**（または設定タブ →「からだの情報と目標を設定」）で
身長・年齢・性別を入れてください。**体重と体脂肪率は体重タブの記録（いちばん新しいもの）**をそのまま使うので、
体重を測り続けているかぎり、目標カロリーも自動で更新されていきます。

### 何を計算しているか

| 数字 | 出し方 |
|---|---|
| 基礎代謝（BMR） | **体脂肪率を記録していれば**除脂肪体重から（Katch-McArdle式）。無ければ身長・体重・年齢・性別から（Mifflin-St Jeor式） |
| 1日の消費（TDEE） | 下の2つの方式から選べます |
| 目標カロリー | 1日の消費 × 目標（しっかり減量 −20% 〜 しっかり増量 +15%） |
| P（タンパク質） | 体重1kgあたり 1.6〜2.4g（既定 2.0g） |
| F（脂質） | 目標カロリーの 20/25/30%（既定 25%）。**体重×0.6g を下限**にしています |
| C（炭水化物） | 残りのカロリーぶん |

体脂肪率が入っていればそちらを優先するのは、**筋トレしている人は身長からの式だと基礎代謝が低めに出やすい**ためです。

### PFCは「おすすめ」が出ます

PとFの選択肢には、**いま選んでいる目標に合わせたおすすめ**が付きます（見出しの横に「おすすめ 2.2g」、
その選択肢に小さな点）。ボタン1つでその組み合わせにできます。

| 目標 | おすすめ | 理由 |
|---|---|---|
| 減量（−15%以下） | P 2.2g・F 25% | カロリーが足りない状態では体が筋肉も分解するので、タンパク質を多めにして守ります |
| ゆっくり減量（−10%） | P 2.0g・F 25% | 標準的な配分 |
| 維持 | P 2.0g・F 25% | 標準的な配分 |
| 増量（+10%以上） | P 1.8g・F 25% | トレーニングを支える炭水化物にカロリーを回したいので、タンパク質は控えめでも足ります |

脂質がどの目標でも25%なのは、20%を切るとホルモンに響き、30%を超えると炭水化物が足りなくなりやすいためです。

**目標そのもの（減量か増量か）には、おすすめを付けていません。**それは本人が決めることなので、
代わりに「1週間で約◯kg」の予測と、選び方の一言だけを出しています。

### 1日の消費カロリーの出し方は2通り

- **活動レベルから**（既定） — 基礎代謝 × 1.2〜1.9。運動ぶんも係数に含まれるので**毎日同じ数字**になります。
  参考として、その日の記録から計算したトレーニング／ウォーキングの消費も表示します（**二重に足さないよう**注記つき）
- **毎日の記録から** — 生活ぶん（基礎代謝 × 1.2〜1.5）＋ **その日に記録したトレーニングとウォーキング**。
  動いた日と休んだ日の差が見えます。目標は「直近14日の平均」と「その日の実績」の**大きい方**を使うので、
  日中に目標が下がることはなく、動いたぶんだけ食べられる量が増えます

運動の消費は **METs × 体重 × 時間 × 1.05** で推定します。有酸素は記録した秒数から、
筋トレはセット数×（動く時間＋その部位のインターバル）で所要時間を出します（開始〜終了が記録されていればそちらを優先。
ただし終了を押し忘れたときのために、4時間を超える記録は時計を使わずセット数からの見積りに戻します）。
ウォーキングは距離を入れてあれば、そのペースからMETsを選びます。

### 記録のしかた

- 時間帯（朝／昼／夜／間食）ごとに「＋ 追加」→ **食品リストから選ぶ**（`foods.js` に79件）。
  100gあたりの食品はグラム、1個単位の食品は個数を入れると、カロリーとPFCがその場で出ます
- 一覧に無いものは「**手で入力**」。パッケージの栄養成分表示をそのまま入れてください。
  **カロリーを空けておくとPFCから計算**します（P4・F9・C4kcal/g）
- 一度記録したものは「**よく食べるもの**」にチップとして並び、タップだけで今の時間帯に追加できます
- 記録をタップすると修正・削除ができます。`‹ 前の日` で過去の日も記録・修正できます
- 直近7日の摂取グラフに目標の点線が入ります。**1日ずつの上下より、1週間の平均**を見てください

数字はすべて推定値です。2週間ほど記録して体重が思った向きに動かなければ、目標を100〜200kcalずらしてください。

## 体重の測り忘れを防ぐ

### アプリ側

記録タブの上に「**今日の体重がまだです**」と出ます。その場で ± と「記録」だけで入力できるので、体重タブまで移動する必要はありません。

- 前回の体重が初期値で入っています。同じならそのまま「記録」を押すだけ
- 記録済みの日は出ません。「あとで」で今回だけ引っ込みます
- **連続記録日数**が出ます（「3日連続で記録中。今日で4日目です」）。体重タブの右上にも表示されます

### iPhone側：毎朝7時のプッシュ通知（2026-07-29 実装）

設定タブの「毎朝の通知」→「**通知をオンにする**」を1回押すだけで、
**毎朝7:00に「体重を測りましょう」の通知が届きます**。アプリを閉じていても届き、タップするとKasaneが開きます。
文面は4種類の日替わり。「テスト通知を送る」でその場で確認できます。

仕組み（Web Push）:

- iPhone側: ホーム画面に追加したKasane（iOS16.4以降のPWA）が購読を作り、`POST /subscribe` でiMacに登録
- iMac側: `tools/server.py`（配信サーバー）が購読を `tools/push-subs.json` に保存。
  毎朝7:00に launchd（`com.morikastu.kasane-push`）が `tools/send_push.py` を実行し、
  Appleのプッシュサーバー経由で通知を送る
- 鍵: `tools/vapid.json` / `tools/vapid.pem`（VAPID鍵。**秘密鍵なのでgit管理外**）
- ログ: `~/Library/Logs/kasane-push.log`

時刻を変えたいときは `~/Library/LaunchAgents/com.morikastu.kasane-push.plist` の Hour/Minute を書き換えて
`launchctl unload → load`。通知はサーバーが要るため **Tailscale版のみ**（github.io版では使えません）。

（旧方式＝iPhoneのショートカットで毎朝Kasaneを開くオートメーションも引き続き併用できます）

## データについて

データはブラウザのlocalStorageにのみ保存されます。サーバーには何も送信されません。

**機種変更やブラウザのデータ削除で消えるため、設定タブから定期的にバックアップ（JSONファイル）を書き出してください。**

### アプリを更新したいとき

ホーム画面から開くとSafariの再読み込みボタンが無いので、**設定タブ →「最新版に更新」**を用意しています。

- Service Worker とキャッシュを消してから読み直します。**localStorageの記録には触れません**
- 新しいバージョンが来ていると、ボタンの下に「新しいバージョンがあります」と緑で表示されます
- Mac側でコードを変えたのにiPhoneの画面が古いままのときは、これを押してください

コードを変えたら `sw.js` の `CACHE` の番号（`kasane-vN`）を上げると、更新が確実に届きます。

**`data.js` や `figures.js` を直したときは、`index.html` の読み込み部分の `?v=` の数字も一緒に上げてください。**

```html
<script src="figures.js?v=3.1.2"></script>
<script src="data.js?v=3.1.2"></script>
```

URLが同じままだと、ブラウザ自身のキャッシュ（Service Workerとは別物）が古いファイルを使い続けます。
実際に2026-07-27、`index.html` だけ新しく `data.js` が古いままになり、記録タブが開かなくなりました。
番号は `APP_V` と揃えておくと分かりやすいです。

### プリセット種目を増やしたとき

`index.html` の `SEED` に種目を足したら、すぐ下の **`SEED_V` の番号を1つ上げて**ください。
すでに使っている端末でも、次に開いたときに**不足分だけが自動で追加**されます。

- 追加しかしません。既存の種目・記録・IDには一切触れないので、データが消えることはありません
- 自分で削除した種目は、次に `SEED_V` を上げるまで復活しません
- 種目を減らしたい場合は自動では消えません。種目タブの × から手動で削除してください
